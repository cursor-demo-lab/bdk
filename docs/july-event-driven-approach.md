# July event-driven approach for the factory (hosted v2)

Read at: `~/git/everysphere` `main` @ `9a4aaa485b78d36c9c68fa78043ed20749abaf57` (`packages/agent-serve` = `@cursor/bdk` 0.2.1 source, formerly `@cursor/july`); published `@cursor/july@0.2.1` `dist/docs` in `factory-desk/node_modules` (same text, `agent/` paths); `~/git/apj-gtm` @ `2848a7537ac50c018a07a46ddab129c8aaec05eb` with the branch's uncommitted edits. Read-only; nothing deployed.

## Recommendation

Keep five slugs and make the systems of record the bus, the way `factory/sandy` does: host code (channel hook, not the model) receives a verified event, decides, claims a natural key in `host.kv` (read then put: `host.kv` has no compare-and-set, see the Superseded note below), and actuates; the next stage is woken by the artifact the previous one wrote (a Jira comment, a GitHub comment, a Slack post), never by a peer call. On hosted v2 that is the only shape that works: the public alias serves authored `/v1/channels/{id}` routes only (`/v1/mcp`, playground, health 404), so `defineConnection({ agent })` cannot resolve across slugs, and every custom HTTP delivery is an isolated `evt:` one-shot with a control-plane-minted delivery id, so the KV claim, not the continuation token, is the idempotency guard. Concretely: triage → planner and planner → desk become Jira `comment_created` webhooks into `publicEndpoint()` + HMAC routes; desk → fixer becomes a GitHub PR comment the fixer's `githubChannel` `onComment` claims; desk → planner "ask" becomes a read of the `Plan:` comment. Two things do not exist yet and must be designed around: Slack Approve/Deny cards have no v2 interactivity ingress (the manifest validator rejects `interactivity.request_url`), and `defineSchedule` `run` handlers do not compile to Temporal calendars.

## Evidence

### 1. Inbound mechanisms on v2 and delivery semantics

- **Authored HTTP channel (webhooks).** `defineChannel` routes mount at `/v1/channels/<id>/…` (channels.md:26-55); handler gets `send`, `callTool`, `waitUntil`, `host`, `auth` (channels.md:76-91). Zod `bodySchema` required on POST (channels.md:57-72). Auth policies: `hmacSignatureAuth({ header, secret })`, `sharedSecretAuth`, `publicEndpoint()` (channels.md:149-163). Hosted v2: `ANY …/internal/agentsdk/agents/{applicationId}/engine/v1/channels/{channelId}[/path]`, 202, claim-checked, Temporal `evt:` lane, replayed into the handler in the VM (ADR 0003:13-38, 141-151). CP verifies HMAC/shared-secret before compute, constant-time, unset secret admits nothing (ADR 0003:121-129); `publicEndpoint()` routes are admitted and metered and the handler's 4xx becomes a cheap `skip` (ADR 0003:105-108). Body ≤ 256 KiB, ≤ 64 headers (ADR 0003:133-135). Rate limits 600/min probe, 120/min deployment, 429 + Retry-After (ADR 0003:114-118). **Retries/dedupe:** HTTP delivery id is CP-minted `httpreq:<uuid>` per request (`agentsdkHttpIngress.ts:440`), so a sender retry runs twice; `catch.idempotencyHeader` is an open question (ADR 0003:183-185). **Ordering:** every HTTP delivery is `evt:`, parallel, no continuation key (ADR 0003:194-196; ADR 0001:846-849). At-least-once starts at durable signal; before that is fail-open (ADR 0001:614-620).
- **Slack.** Hosted v2 is Events API on the control plane, per-agent app, no `xapp-` token (ADR 0002:113-119; `agentsdk-v2-unsupported.md:59`); Socket Mode only for local `dev`. Dedupe on Slack `event_id`, shared by `x-slack-retry-num` redeliveries (ADR 0002:227-231; `agentSdkSlackAppEvents.ts:394`); 200 inside 3 s, then handoff (ADR 0002:184-188; `agentSdkSlackAppEvents.ts:96`). Threads take the `cont:{channelId}:{threadTs}` FIFO lane (ADR 0002:233-239). Fast ack (`eyes` reaction / `setStatus`) is posted by the CP after the dedupe claim (ADR 0002:263-300; `agentSdkSlackFastAck.ts:185`). Channel watch: `channelPosts.allow` needs 1–10 channel ids, each becomes a subscription edge, posts outside drop at ingress, `debounceMs` ignored (slack.md:110-151; ADR 0002:525). Mentions/DMs coalesce (sessions.md:59-66).
- **GitHub.** `githubChannel({ cursorAccount: { repos } })` pulls events from Cursor, no public webhook or App (github.md:16-19). Hooks `onPullRequest/onComment/onIssue/onCheckSuite/onCheckRun/onWorkflowRun/onStatus/onEvent`, each returning `{ auth }` (model turn), `{ task }` (host code), or `null` (github.md:188-198). Only event types the pinned manifest names are delivered (ADR 0001:919-926). Dedupe on `{provider, deliveryId}` (ADR 0001:643-645, 687-690). Direct webhook + secret also supported (github.md:296-321).
- **Schedules/reminders.** Markdown `cron:` and `defineSchedule` (schedules.md:24-66). On v2 only `prompt`/`receive` compile to Temporal calendars; a TypeScript `run` that `callTool`s or waits does not fire (`agentsdk-v2-unsupported.md:56`, 123-125). Reminders need a continuation key and a named handler (`unsupported.md:44-47`).
- **Jira.** No first-class channel. `issuesChannel` is Factory `issue.created`, not Jira (channels.md:186; `issues-channel.ts:10-29`). Jira is (a) outbound via the Cursor-account Atlassian MCP connector (`templates/triage.md:42-47`) and (b) inbound via a signed `publicEndpoint()` webhook, as `triage-jira` does today (`webhook.ts:9-46`, `templates/triage.md:69-71`).

### 2. State primitives

`host.kv` is durable JSON KV that survives replacement (types.ts:600-607; deployment.md:151-155). Superseded (2026-09-24): the types define CAS (`getWithVersion`, `putIfAbsent`, `putIfVersion`, `listKeys(prefix)`, types.ts:662-674) for storage backends, but the agent-facing `host.kv` never implements it on any backend (`july:dist/internal/host-kv.js:22-34`), so every `putIfAbsent` below is really read then write; the desk's claims are best effort, verified after write (`factory-desk/agent/lib/kv-verified.ts`; [bugs.md ask 11](bugs.md)). Rate-limited per deployment via Statsig `agentsdk_store_rate_limits` (`agentsdkStoreRateLimit.ts:16-26`). `host.files` for file-shaped state (types.ts:608-615). KV is per deployment, so cross-slug correlation is by natural key in the system of record (issue key, PR number), each slug holding its own claims. Slack thread identity rides `auth.attributes.channel_id/thread_ts` (`slack/auth.ts:37-38`; desk `threads.ts:17-31`). Process `Map`s, timers, parked approvals die on replace (`unsupported.md:53`; deployment.md:157-159).

### 3. Subagents vs separate slugs

Subagents are mid-turn delegates via the `task` tool, inherit the parent's tools/connections/channels, own no channels or schedules (subagents.md:8-12, 41-46). They cannot be woken by an event, so they do not replace a stage that a Jira/GitHub event must start. The docs' rule: subagent for roles inside one job, peer/full agent when the specialist is independently run and inspected (subagents.md:54-58; agent-to-agent.md:115-125). Peers need one multi-agent host and loopback (agent-to-agent.md:141-148); v2 alias 404s `/v1/mcp` (`unsupported.md:58`). Folding planner into desk as a subagent is legitimate only if planning is never triggered by a Jira event, which contradicts the triage → planner edge. Keep five slugs. Precedent: hosted v1 `asml-router` and `triage` reach peers over `*_ALIAS_TOKEN` + `*_MCP_URL` secrets and `*.agents.cursorusercontent.com` egress (`agent-sdk deployment asml-router --json`, secrets redacted); that is a direct network flow and does not work on v2.

### 4. Sandy as the reference

Trigger: `slackChannel` with `engagement.channelPosts` allowlist, `posts: "top-level"`, `onChannelPost` (`sandy/agent/channels/slack.ts:58-76`). Decide in pure code: skip bot/empty/duplicate/gate-off (`decision.ts:93-113`), claim key `sandy:{workflow}:{channel}:{threadTs}` (`decision.ts:51-57`). Persist: claim in `host.kv` before actuation, release only when the session never started, drop records at a natural key because Slack never redelivers an acked post (`channel-post.ts:94-124`; `run-records.ts:25-35, 84-90`); activity is a log line, not KV (`channel-post.ts:142-146`). No agent calls: work runs as a Cursor cloud session via `@cursor/sdk` `Agent.create` with `idempotencyKey = claimKey` and the skill read from the checkout (`dispatch.ts:55-64`; `prompt.ts:11-22`). Deploy: `runtime: "local"`, `hosting.secretNames`, `egressDomains: ["api.github.com"]` (`agent.ts:25-32`). Test: unit tests over the decision function, a two-process dedupe test over file KV, one mention smoke eval, `scripts/synthetic-post.ts` replay (`evals/README.md:3-9`; `dedupe.two-process.integration.test.ts:85-86`; `synthetic-post.ts:1-7`; `mise.toml:19-22`). Known v2 gap: in-process serial queue for the check-then-put race (`serial-queue.ts:3-16`); `putIfAbsent` would replace it, but `host.kv` does not offer it ([bugs.md ask 11](bugs.md)).

### 5. Gotchas

- **Slack approvals on v2.** `toolApprovals` cards need interactivity; the v2 manifest validator rejects `settings.interactivity.request_url` ("agent-serve is Socket-Mode-only", `agentServeSlackProvisioning.ts:1100-1106`) and no v2 interactivity ingress exists in `backend/server/src/agentServe` or `factory/agent-sdk` (ADR 0002:429-441 lists it as track C3). The desk's `cloud__launch` approval card will not resolve on hosted v2 today; use a text reply (`approve KEY`) as the gate.
- **Egress.** Exact host unless `*.`; Slack needs both `slack.com` and `*.slack.com` (`factory-desk/agent/agent.ts:17-19`). Redeploy replaces CLI-supplied egress and `--cursor-events-repo` (deployment.md:140-143). Keep egress in the `hosting` block.
- **Secrets at boot.** Values are set after the deployment exists, then redeploy (deployment.md:64-94); a module-load throw on a missing secret prevents the freeze from starting so secrets never attach (`factory-desk/agent/extensions/cloud.ts:4-8`). Read env lazily. Never `CURSOR_*` names (deployment.md:89-90).
- **Webhook secrets.** `publicEndpoint()` = handler verifies; CP-side `hmacSignatureAuth` needs the secret name declared and set or admits nothing (ADR 0003:103-110, 126). Jira Automation webhooks are unsigned; use a system webhook with a secret.
- **Slugs.** `/^[a-z0-9_-]{1,64}$/`, lowercased (`deploy-client.ts`; `cli-deploy.ts:442`). `triage-jira`, `triage-fixer`, `security-help-agent`, `factory-desk` are taken as v2 applications (`agent-sdk deployments --json` → `applications`); prefix the other four.
- **`--prod`.** v2 `run --prod` uses the internal start route, not the alias (ADR 0003:154-159). Local `serve --dir .` keeps Socket Mode and in-process peers; hosted has neither (`unsupported.md:137-140`).
- **Model.** `grok-training-latest` is in the catalog (`modelIds.ts:203`); not referenced anywhere in `packages/agent-serve`, so treat as an internal id with no framework default.
- **Continuation on custom routes.** `continuationToken`/`admission: "coalesce"` on a custom channel does not serialize hosted deliveries; each is `evt:` (ADR 0003:194-196). Two `comment_created` deliveries for one KEY can run in parallel VMs. The KV claim is the guard.

## Differences from `docs/event-driven-factory-design.md`

The draft and this note agree on the edges, the sentinels, the claims, and keeping five slugs. Differences:

1. The draft keeps the desk's `cloud__launch` approval card. At this commit that card cannot be clicked on hosted v2 (no interactivity ingress). Replace with a text `approve KEY` reply, or accept that launches stay local-only until C3 lands.
2. The draft's planner route relies on `continuationToken: issue:<KEY>` + `coalesce` to avoid rival plans. On hosted v2 that gives no serialization; make the kv claim on `plan-claimed/<KEY>` (read then put; `host.kv` has no compare-and-set) the only guard and treat the token as a local-dev nicety.
3. The draft says the Jira comment webhooks return 200; on hosted v2 the CP answers 202 and the handler's response is not seen by Jira (ADR 0003:13-17, 148-150). Jira retries on non-2xx only, so the CP 202 is what matters.
4. The draft names the shared secret `JIRA_WEBHOOK_SECRET` on three slugs; each is a separate installation secret and must be set on each (deployment.md:82-84).

## Open risks

- `catch.idempotencyHeader` does not exist; Jira retries of one comment reach two VMs. The claim covers `send`; a host-only `announce_plan` post also relies on its claim (best effort, verified after write; agent kv has no CAS).
- No v2 schedule `run`; any polling fallback (for example "did the `Plan:` comment land") must be a reminder with a named handler or a markdown cron prompt.
- `channelPosts` on v2 cannot watch `"*"` and drops edits; the desk stays mentions/DMs, so unaffected.
- `hosting.egressDomains` for `*.atlassian.net` is needed if the desk reads Jira over REST rather than the Cursor MCP connector (precedent `triage` egress list).
