# Slack patterns in everysphere for the factory desk

Read at `<PRIVATE_MONOREPO>` `main` @ `9a4aaa485b78d36c9c68fa78043ed20749abaf57`. Surveyed 24 `factory/*/agent/channels/slack.ts` plus the framework pack `packages/agent-serve/src/channels/slack/`. `asml-router` and `triage` are not in the monorepo (deployed from `Rperry2174/asml-gtmko-overlay-demo` and `jgrace19/grafana-triage-agent`; `agent-sdk deployment <slug> --json`, secrets redacted); only their hosted shape is cited. ## Adopt these

1. **Sandy's watch-and-claim shape for anything a non-human event should start.** `onChannelPost` on an allowlisted channel, host code decides, a `host.kv` claim at `{workflow}:{channel}:{threadTs}` is the dedupe, the handler always returns `null` so the model never wakes on a watch (`sandy/agent/channels/slack.ts:41-76`; `decision.ts:51-57, 104-113`). Foreman does the same with `question-claims/{channel}/{threadTs}` and an explicit asymmetric failure posture: failed read = unclaimed, failed write = abort (`foreman/agent/lib/thread-claims.ts:1-17`).
2. **Persist `{channelId, threadTs}` under a natural key from inside the session that owns the thread.** Debug's `watch-pr` tool writes `pullRequestThreadKey(owner, repo, n) → { channelId, threadTs }` while the turn runs (`debug/agent/tools/watch-pr.ts:41-44`), and its Origin channel later reads it on `pull_request.merged`, returns `{ task }`, posts with `postMessage({ botToken, channel, threadTs })`, and deletes the key (`debug/agent/channels/origin.ts:20-40`). Thread identity comes off `session.auth.attributes.channel_id/thread_ts`, which the pack stamps (`packages/agent-serve/src/channels/slack/auth.ts:37-38`); the desk's `threadFromSession` already reads it (`factory-desk/agent/lib/threads.ts:17-31`). Jenny records `mentioned/{channel}/{threadTs}` markers the same way (`jenny/agent/channels/slack.ts:25-27`; `jev-slack-wake.ts:244-253`).
3. **Claims are best effort.** Superseded (2026-09-24): `ctx.host.kv` has no compare-and-set on any backend in July 0.2.2: `createHostKvApi` returns only get, put, and delete, hosted and local (`july:dist/internal/host-kv.js:22-34`); `HostKvCasApi` is for storage backends, not `host.kv`. The desk claims read, then write, then re-read to verify (`factory-desk/agent/lib/kv-verified.ts`). Drop the compare-title fallback once hosted.
4. **Bot-echo and feed filtering in host code, on `author.isBot`/`botId`.** The pack drops bot-authored mentions and DMs unless `includeBotAuthored` (`inbound.ts:118-123`); sandy treats unknown authorship as bot (`slack.ts:24-26`); debug's `isNewAlert` requires `author.botId` for feed alerts and `ts === threadTs` for top-level (`debug/agent/channels/slack.ts:100-110`). On hosted v2 the control plane also drops `bot_id`/own-bot events at the edge (ADR 0002:189-194).
5. **Let the platform dedupe Slack retries; keep the local guard.** Pack: per-mount FIFO `event_id` set of 2000 (`event-id-dedupe.ts:1-13`). Hosted v2: `event_id` is the `{provider, deliveryId}` claim and is shared by `x-slack-retry-num` redeliveries (`agentSdkSlackAppEvents.ts:394`; ADR 0002:227-231).
6. **Acknowledge with a reaction, not a message.** Deploy-buddy: `eyes` on engage, `alarm_clock` when a reminder arms, `white_check_mark` on success (`deploy-buddy/agent/lib/slack-reactions.ts:14-19`). Hosted v2 posts the `eyes`/`setStatus` ack from the control plane after the dedupe claim, so authored acks should be idempotent (`agentSdkSlackFastAck.ts:185`; ADR 0002:263-300).
7. **Reply mode `post` with `status.idle` lines** for a desk that files tickets (patches `slack.ts:181`, sherlock `:72`); `stream` + `toolCards` for investigative agents (foreman `:45-49`, grclanker `:151-155`); `agentic` only with the `slack-communication` extension (jenny `:18-23`, robomax `:21-28`).

## Evidence by topic

**(a) `slackChannel` configuration.** Every agent sets `envPrefix` (tokens `<PREFIX>_SLACK_BOT_TOKEN` / `_APP_TOKEN`; AGENTS.md "one Slack app per agent"). Transport: Socket Mode locally; hosted v2 skips Socket Mode and takes Events API from the control plane, no `xapp-` token (`agentsdk-v2-unsupported.md:59`; ADR 0002:113-119). The three v2 team apps carry only `*_SLACK_BOT_TOKEN` in `secretNames` (`agent-sdk deployment triage-fixer|security-help-agent --json`). `toolApprovals: true`: grclanker (author-scoped approvals, needs interactivity, `slack.ts:129-132`), factory-desk. Explicit `false`: decision-log `:10`, runbook `:6`. `engagement.channelPosts` with `allow` ids + `posts: "top-level"`: sandy, foreman `:33-36`, grclanker `:143-147`, patches `:203-211`, sherlock `:355-361`, sphere `:109-114`, vendor-intake `:190-198`; debug uses `posts: "all"` for alert threads `:315-318`. `debounceMs` is local-only, ignored hosted (grclanker `:125-127`; slack.md:147-149). `suggestedPrompts` + `suggestedPromptsTitle` on nearly all. `policy.blockExternals: true` explicit on patches `:199-201` and vendor-intake `:155-157`; sherlock sets `false` because Slack Connect posters became guests (`sherlock/agent/channels/slack.ts:48-54`); grclanker `respondTo: "author"` `:95`.

**(b) Thread references.** See Adopt 2. Keys are natural (`ticket/<KEY>`, `pr/{owner}/{repo}/{n}`, `question-claims/…`), values `{ channelId, threadTs }`, stored in `host.kv`, never in session state or process maps (`unsupported.md:53, 134-135`). Debug additionally records `threadOwnerKey → { ownerId }` to gate who may continue (`debug/agent/channels/slack.ts:86-90`).

**(c) Interactive cards.** Approval cards encode `{ sessionId, callId }` in the action value (`approvals.ts:12-33`); the pack parses `block_actions` and calls `resolveApproval` (`interactive.ts:187-196, 174`). Ack timing: Socket Mode acks the envelope, then resolves. Hosted v2: the manifest validator rejects `settings.interactivity.request_url` (`agentServeSlackProvisioning.ts:1100-1106`) and no `/agent-sdk/slack/interactivity` handler exists under `backend/server/src/agentServe` or `factory/agent-sdk`; ADR 0002:429-441 lists it as a later track. Parked approvals live in fork memory and die on replace (ADR 0002:436-441; deployment.md:157-159). No surveyed agent relies on cards for a cross-agent gate; grclanker uses them for a single-user upload.

**(d) Cross-agent coordination without direct calls.** Sandy → cloud session via `@cursor/sdk` with `idempotencyKey` (`dispatch.ts:55-64`). Debug: Slack thread → `watch-pr` KV → Origin merge event → thread post (`origin.ts:20-40`). Lasso and access-reviewer, which call peers over `/v1/mcp`, are pinned to v1 for that reason (`unsupported.md:76-77`). Hosted precedents `asml-router` and `triage` reach peers over `*_ALIAS_TOKEN` + `*_MCP_URL` secrets with `*.agents.cursorusercontent.com` egress, a v1-only shape.

**(e) Dedupe and loops.** Adopt 4 and 5. `botName`-style self-filtering is implicit: the pack never wakes on its own posts (`inbound.ts:118-123`). Sandy's in-process `createSerialQueue` closes the check-then-put race in one process only (`serial-queue.ts:3-16`); `putIfAbsent` would replace it, but agent `host.kv` has no compare-and-set ([bugs.md ask 11](bugs.md)), so the claim stays read then put.

**(f) Framework internals worth copying.** Delivery logs: `reply delivered via postMessage` (`defaults.ts:284`), `via progress update` (`:262`), `via stream` (`live-delivery.ts:425`). Hooks can post before the turn: `ctx.thread.post("Looking at this now.")` (slack.md:207-229). Permalink builder: `slackPermalink` (`sandy/agent/lib/domain.ts:28-30`). Redaction of tool args on cards (`approvals.ts:76`). Hosted admission is sessionless and refuses `send({ continuationToken })` on the pack; threads are keyed `cont:{channelId}:{threadTs}` above the handler (`unsupported.md:21-23, 43`; grclanker `slack.ts:122-125`).

## What the desk does differently today

- Mentions + DMs only (`factory-desk/agent/channels/slack.ts:6-11`); intentional, matches the recommendation. No channel watch needed.
- Relies on `toolApprovals: true` + `cursorCloudAgents({ needsApproval: true })` cards for the launch gate (`slack.ts:8`; `extensions/cloud.ts:20-24`). Not deliverable on hosted v2 today; switch to a text `approve KEY` gate or hold launches local.
- Stores `ticket/<KEY> → thread` (`file_ticket.ts:36`) and `announced/<KEY>` claim; correct shape. Missing: a `plan-claimed/<KEY>` claim on the planner side, and deletion of the `ticket/<KEY>` binding once the ticket closes (debug deletes on merge, `origin.ts:37`).
- Posts back over `ctx.host.slack.getClient().chat.postMessage` from a tool the *planner* calls across a peer (`announce_plan.ts:1-4`). Debug's shape is a channel `{ task }` on the desk's own slug triggered by the system of record.
- No reaction ack; the desk's `reply: { mode: "post" }` status chip is the only feedback.
- Peer stubs `peerConnection` gated by `FACTORY_INPROCESS_PEERS` (`lib/peers.ts:3-8`); no surveyed everysphere agent ships a hosted peer edge.
