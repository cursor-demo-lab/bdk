## pr-autofixer edit for the automatic fix

- pr-autofixer/agent/channels/github.ts: `wake()` no longer drops every undriven PR. `autoDrive()` runs for a `check_run` or `status` event on an undriven PR, fetches the head ref and title (`fetchPrHead`, one GraphQL read), and when either starts with a key in `FACTORY_JIRA_PROJECTS` (or the override `PR_AUTOFIXER_AUTO_DRIVE_PROJECTS`; an empty list means no automatic drive, and nothing is written in code) claims the PR once (`auto-drive:<pr>` in `host.kv`) and starts `drive_pr` through the channel's `callTool`, the same path a person's `fix <PR URL>` takes. A start that fails (`ok: false` or a throw) releases the claim, and a claim older than `START_LEASE_MS` (10 minutes) with still no drive is retaken, so a later red check tries again. The red event itself is not buffered; the drive's first turn triages it. `Runtime` gains `callTool` from `onStart`. This is the template's first behaviour edit beyond `repos.ts`; the upgrade path in `plan.md` must re-apply it.
- pr-autofixer/agent/lib/auto-drive.ts (+ test): the decision, the project list, the claim key, the head fetch.
- pr-autofixer/agent/lib/auto-drive.ts `claimAutoDrive`: `host.kv` has only get, put and delete (no compare-and-set on any backend), so the claim is best effort, verified after write (`agent/lib/kv-verified.ts`): the claim is a lease (`agent/lib/claim-lease.ts`, shared with factory-desk): it writes `{ state: "pending", owner, at }` with a fresh owner token and holds the claim only if the read-back shows that owner, so a red `check_run` and a red `status` for one push that race on the empty key yield one drive. The residual window is a second write landing after the first one's read-back, when both drive. A lease whose time cannot be parsed counts as expired, and a value that is not a lease (a pre-lease `{at, token}` claim, or garbage) is cleared and retaken at once, so one bad kv value cannot hold a pull request red forever. Every claim write, the start, the mark, the stamp and each release retry in the handler before failing loudly, since nothing redelivers the event.
- pr-autofixer/agent/channels/github.ts, agent/lib/auto-drive.ts `startAutoDrive`: the channel returns the `drive_pr` start as the hook's `task` instead of floating it, so the host's `waitUntil` window stays open until `drive_pr` has answered. A refused start, an error envelope, or a thrown peer call releases the claim and never rejects.
- pr-autofixer/agent/lib/start-drive.ts, agent/tools/drive_pr.ts, agent/channels/drive.ts: `startDrive` takes `repos` and refuses a pull request outside the list with code `out_of_scope`, naming the configured list, before any GitHub read; matching is case-insensitive. Both callers pass `githubRepos()`. Before this the `cursorAccount` subscription bounded what GitHub delivered, not what a person pasted after `fix` or what `POST /drive` received, and `fetchPrState` swallows errors, so the drive proceeded.
- pr-autofixer/agent/tools/drive_pr.ts, security-reviewer/agent/tools/post_findings.ts: both declare `effect: "write"` and a `dryRunResult` in their own result shape; `drive_pr` also refuses an eval session (`code: "eval"`), as `record_plan` and `post_findings` already did.
- pr-autofixer/agent/lib/config.ts (+ test), agent/lib/repos.ts: `repos.ts` keeps the template's exported names but the literal array is gone; it reads `PR_AUTOFIXER_REPOS`, then `FACTORY_REPOS`, and throws `FactoryConfigError` naming both when neither is set, at module load, because the channel declares its scope at boot. `config.ts` is one of four identical copies (desk, planner, fixer, reviewer). `agent/channels/slack.ts`: the suggested prompt names the configured repository, or none.
- security-reviewer/agent/lib/config.ts (+ test), agent/lib/repos.ts: the same change with `SECURITY_REVIEWER_REPOS` as the override. `agent/channels/github.test.ts` (both GitHub projects): the channel's declared settings through `getGitHubChannelOptions`, and one out-of-scope event through `dispatchGitHubWebhook` produces no send. The `cursorAccount` subscription bounds what the fixer's handler is delivered, and `startDrive` now refuses `out_of_scope` itself for anything pasted or posted (see below).
- pr-autofixer/package.json, package-lock.json: `tsx --test agent/lib/*.test.ts` and the `tsx` devDependency.
- pr-autofixer/agent/lib/webhook-buffer.ts (+ `webhook-buffer.test.ts`): the debounce timer catches and logs a failed `flush` (`[pr-autofixer] webhook buffer: flush of <pr> failed: …`) instead of `void`-ing it. `flush` already reschedules a failed entry before it rethrows, and only the timer calls it, so the rethrow was only ever an unhandled rejection every `debounceMs` (round-2 finding 7); debounce and retry are unchanged.
